### #6 - Intelligence Engine Prompt Optimization (Anti-Fluff & Smart Extraction)

**What & Why**
The MapReduce pipeline is now mechanically stable and successfully processing 400+ extractions, but the resulting dashboard is too vague ("fluffy") and sometimes fails to render charts because the underlying extracted data lacks quantitative anchors. We need to upgrade the system prompts in Phase 0 and Phase 3 to force the LLMs to extract hard data (dates, dollars, names) and synthesize it with extreme density. We must also introduce conditional rendering logic so the AI only generates a chart when it actually adds analytical value, rather than forcing a useless graphic just to fill the schema.

**Done looks like**

* Phase 0 generates granular JSON schemas that explicitly request dates, financial impacts, specific names, and categorical tags.
* Phase 3 synthesis outputs dense, Axios Smart Brevity-style bullet points with bolded entities and exact numbers.
* Vague adjectives ("various", "several", "significant") are virtually eliminated from the output.
* Charts (`bar_chart`) are only rendered when robust time-series or categorical comparison data exists; otherwise, the AI intelligently relies on `stat_card` and `summary_text` widgets.

**Out of scope**

* Changing the underlying MapReduce execution logic, batching, or payload compression built in Tasks 4 & 5.
* Modifying the React frontend or the `DynamicReportPayload` TypeScript schema.
