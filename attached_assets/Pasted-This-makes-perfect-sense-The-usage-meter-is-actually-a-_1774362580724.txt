### #15 - Civic Ledger UI Polish & Document Browser Refinements

**What & Why**
The new Documents browser and Civic Ledger shell are structurally sound, but the UI has several rough edges that make it feel like an internal tool rather than a consumer product. There is a redundant "double masthead" (logo in both the sidebar and header). The desktop calendar view stacks awkwardly instead of sitting side-by-side. Document cards expose internal backend state (e.g., "Needs Review" badges, raw `.pdf` filenames, unformatted OCR text walls). Finally, the API usage meter in the header lacks context, looking like a broken loading bar rather than a usage quota. 

**Done looks like**
* **Single Masthead:** The OPENCouncil logo only appears in the sidebar on desktop, and only in the top header on mobile. The desktop header space is used for contextual page titles/breadcrumbs (e.g., "Documents").
* **Usage Meter Polish:** The progress bar is clearly labeled to indicate quota (e.g., "Guest Usage", "Free Tier") alongside the percentage, so it is immediately understood as an API/query limit.
* **Desktop Calendar Layout:** The calendar and the filtered document list sit side-by-side on desktop displays (e.g., a 4-col / 8-col split), and stack cleanly on mobile.
* **Document Card Polish:** Raw filenames are hidden. The UI displays the `canonicalTitle` (stripping `.pdf` and formatting cleanly if a fallback is needed). The internal "Needs Review" badge is removed and replaced by the actual Board Name. Preview text is strictly truncated to 3 lines for uniform card heights.

**Out of scope**
* Backend changes to extraction, parsing, or PDF OCR logic.
* Changing the underlying Shadcn Calendar component logic or API fetching.
* Implementing the actual Stripe/billing upgrade flow (UI polish only).

**Tasks**
* **Task 1: De-duplicate the Masthead** — In `CivicLayout.tsx` (or the header component), add Tailwind classes to the header logo so it only shows on mobile (`block md:hidden`). Ensure the sidebar logo only shows on desktop (`hidden md:block`). In the header's left side (where the logo used to be on desktop), dynamically render the current page title (e.g., "Documents", "News Feed").
* **Task 2: Polish the Usage Meter** — Update the usage progress bar in the header. Add a clear, small text label above or beside the bar based on the user's authentication state. If anonymous: "Guest Usage". If authenticated but not paid: "Free Tier". Ensure the layout feels like a quota tracker.

* **Task 4: Fix Calendar Desktop Layout** — In `documents.tsx`, update the layout wrapper containing the Calendar and the List views. Use a CSS grid (`grid grid-cols-1 md:grid-cols-12 gap-6`).
