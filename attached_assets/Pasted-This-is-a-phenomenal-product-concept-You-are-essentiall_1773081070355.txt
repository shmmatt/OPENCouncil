This is a phenomenal product concept. You are essentially building a "cyborg" journalism workflow. Letting a human steer the AI's research via the Deep Dive chat, and then instantly snapping those findings into the structured Smart Brevity format, is the exact right way to handle complex or nuanced municipal issues that the automated pipeline might miss.

The Replit agent's plan is structurally sound and reuses all the great refactoring work we just did. However, there are two major architectural blind spots in **T001** that will completely break the "Learn More" loop if you don't catch them now.

### 1. The Lost Citations (The Missing Link)

In the fully automated pipeline, the system knows exactly which document IDs it is summarizing. However, in a free-form chat session, the AI is pulling various chunks from the vector database on the fly.

If the agent just sends the raw text transcript to the `generateSummary` LLM, the resulting draft in `town_feed_items` will have an empty `sourceMinutesIds` array. When you eventually publish this feed item and a user clicks "Learn More," the bot won't know which documents to reference.

**The Fix:** Before generating the feed item, the backend needs to scrape the `citations` array from every assistant message in that chat session, deduplicate the document IDs, and save that array to the `sourceMinutesIds` column of the new draft.

### 2. The "Meta-Summary" Trap

LLMs are notoriously bad at summarizing chat transcripts into articles. If you just pass a chat log to the model and say "write a feed item," it will often write about the *conversation itself*.
*(e.g., "Today, an admin asked about the police station. The AI found that it cost $700,000. The admin then asked about the ARPA funds...")*

**The Fix:** You need a strict prompt constraint in T001 that forces the LLM to ignore the conversational mechanics and only synthesize the objective municipal facts into the journalistic format.
