Context & Objective:
We are completely overhauling the fallback architecture of our civic crawler. The current Playwright/Chromium implementation is crashing our server due to out-of-memory (OOM) errors and is failing to bypass Cloudflare Turnstile on heavily protected towns (like Ossipee, Tuftonboro, and Wakefield).

We are moving to a Hybrid Architecture. We will use standard HTTP fetches (Node fetch/axios) for unprotected sites (the "Fast Lane") and seamlessly route protected sites or interstitial pages to a third-party Web Scraping API (the "Heavy Lane") like ZenRows.

Please execute the following tasks in order:

Task 1: Eliminate Playwright/Chromium

Remove all Playwright, Puppeteer, and Chromium dependencies from the project (package.json, install scripts, etc.).

Delete the browserFetcher module and any functions like fetchPageViaBrowser or browserFetchDocument.

Task 2: Implement the "Smart Router" (Fast Lane vs. Heavy Lane)

In the main crawler engine, introduce a dynamic routing logic.

By default, attempt to fetch a page using our standard enriched-header fetch function (Fast Lane).

If the Fast Lane request returns a 403, 429, or if the HTML contains known CAPTCHA/protection markers (like Revize or Cloudflare Turnstile), immediately flag that domain as requires_heavy_lane.

We are currently falling into "interstitial traps" where we download the HTML of a "Your download will begin shortly" page instead of the actual PDF.

Update the fetchDocument function to strictly check the HTTP Content-Type header of the response BEFORE downloading the buffer.

If the URL ends in a document extension (e.g., .pdf) but the Content-Type is text/html, do not save it. Treat this as an interstitial page.
