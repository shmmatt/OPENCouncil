### The Missing Piece: Native API Batching

In **Fix 1**, the agent proposes deduplicating the queries so that instead of sending 6 concurrent HTTP requests to Gemini, it only sends 3 or 4.

While sending 3 concurrent requests is better than 6, it is still relying on `Promise.all` to fire multiple simultaneous HTTP calls, which can still trigger rate limits or serialization delays on the API side.

**The Upgrade:** The Gemini API has a native `batchEmbedContents` method specifically designed for this. Instead of making 3 separate network calls for 3 unique queries, your backend should pass an array of all unique query strings into a *single* API call. Gemini will process them together and return an array of vectors. This reduces your network latency to a single round trip and completely bypasses the concurrent rate-limiting issue.
