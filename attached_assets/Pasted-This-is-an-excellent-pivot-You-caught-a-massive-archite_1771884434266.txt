### The One Catch: The Deduplication Blindspot

Before you tell the agent to build this, there is one edge case in **T002** that will cause massive headaches if not patched now.

The agent states:

> *At the start of a crawl, pre-seed `docsSeen` from existing `crawler_documents` with `status = 'uploaded'` for that town, so the crawler won't re-download docs.*

**The Flaw:** If the crawler *only* pre-seeds `uploaded` documents, it will completely forget about documents that currently have a status of `failed` or `discovered` from a previous run.

**The Result:** 1. The crawler runs Phase 4 (BFS).
2. It finds `minutes-2025.pdf`.
3. It checks its `docsSeen` map. Because the DB row for `minutes-2025.pdf` is currently marked `failed` (maybe due to a temporary WAF block yesterday), it isn't in the pre-seeded map.
4. The crawler says, "Oh, a new file!" and attempts to insert it.
5. The database throws a Unique Constraint violation (or performs an unnecessary upsert), and the crawler wastes time re-processing a link it already knows about.
