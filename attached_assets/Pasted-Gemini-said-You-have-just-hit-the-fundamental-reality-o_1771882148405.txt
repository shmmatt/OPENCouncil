1. The "Town Profile" Concept
Instead of the crawler guessing how to navigate a site, it should read a specific "instruction manual" for each town before it starts. You already have a database table for towns; you need to expand it into a robust JSON configuration object.

A Town Profile should dictate the crawler's behavior:

cms_type: (WordPress, CivicPlus, Revize, Custom) — This tells the crawler which generic rulebook to start with.

protection_level: (Standard, Heavy_Lane, Manual) — Dictates whether to use Fast Lane or route immediately to ZenRows.

custom_path_rules: An array of regex patterns. For Ossipee, this is where you store the rule: "If you see /minutes-NNN, send it to ZenRows to resolve the redirect."

external_repositories: A critical addition for towns like Conway. This holds URLs or IDs for third-party document hosts like Google Drive or Dropbox.

3. Modularizing the Replit Code
To keep the Replit agent from getting confused, the crawler engine needs to be broken into "Handlers."

civicplusHandler.ts (Knows about /node/ paths and redirects)

wordpressHandler.ts (Knows how to read standard category tags)

driveHandler.ts (Talks to the Google API)
