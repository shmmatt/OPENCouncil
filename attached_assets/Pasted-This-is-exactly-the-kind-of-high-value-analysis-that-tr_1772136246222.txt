Phase 1: The Extraction Schema
We need to run a batch process on your vector database of Ossipee documents, specifically targeting Planning Board and Zoning Board of Adjustment (ZBA) minutes. We will use a structured output prompt to force the LLM to extract the data into a strict JSON format for every commercial entity or address mentioned.
We want the LLM to pull:
 * Entity/Project Name: (e.g., "Main Street Retail Expansion")
 * Initial Appearance Date: The first time it hits the Planning Board agenda.
 * Total Continuances: How many subsequent meetings it was bumped to.
 * Initial Outcome: Approved, Approved with Conditions, Denied, or Withdrawn.
 * Primary Reason for Denial/Friction: (e.g., "Parking setback violation," "Drainage concerns," "Abutter noise complaints").
 * Appeal Path (NH Specifics): Did it go to the ZBA? In New Hampshire, if a Planning Board denial is based on a zoning ordinance interpretation (RSA 676:5), the appeal goes to the ZBA. If it's based on the Planning Board's own site plan regulations, it often goes straight to Superior Court (RSA 677:15). We want to track if an applicant fought the denial locally and won.

Once you have this structured data, the best way to present it is visually, treating the municipal approval process like a sales pipeline.
You can build a dashboard that shows the attrition rate of site plans in Ossipee:
 * Top of Funnel (100%): Total Initial Site Plan Applications.

 * Stage 3 (e.g., 50%): Approved without conditions vs. Approved with conditions.

This visual instantly tells a developer or business owner: "If you apply in this town, you have an X% chance of getting approved on the first try, and a Y% chance of getting dragged into a six-month appeal process."

The numbers show what happened; the text extraction shows why. You can aggregate the "Primary Reason for Denial/Friction" field into a categorized matrix.
