Replit Agent prompt (paste as-is)

You are a senior TypeScript/Node engineer acting as an onboarding + architecture reviewer for this repo.

GOAL
- Build an accurate mental model of how OPENCouncil is structured, what runs where, and how the crawler + ingestion + chat pipeline fit together.

CONSTRAINTS
- Only use information from THIS repository. Do not assume missing files exist.
- Prefer evidence: cite file paths and relevant function names when making claims.
- If something is unclear, say exactly what is missing and what you would check next (but do not ask me questions until after your assessment).

TASKS (do in order)

1) REPO TREE + ENTRYPOINTS

  - API server entrypoint(s)

2) DATA FLOW DIAGRAM (TEXT)
Describe the end-to-end data flow in 8–15 bullets:
- Town website discovery → download → storage → DB queue → ingestion → model store → chat retrieval → citations.

3) CHAT PIPELINE
- Identify the current chat route handler(s) and pipeline runner(s).
- Identify where context is built: history selection, retrieval selection, citation formatting.

4) INGESTION / OCR

5) CRAWLER

7) SECURITY + OPS FLAGS (IMPORTANT)

8) OUTPUTS
Produce these deliverables:

A) "OPENCouncil Developer Map" (1–2 pages)

C) "Top 10 Risks / Tech Debt" (ordered)

D) "Next 7 PRs" plan
- 7 small, safe PRs with scope, touched files, and acceptance criteria.
- Prefer refactors that clarify boundaries:
  - split server/routes.ts into routers
  - isolate extraction/OCR behind one interface
  - add env flags for workers
  - add observability for token usage

STOP AFTER DELIVERING A–D.
Do not start coding until I explicitly ask you to implement a specific PR from the plan.

Short synopsis (paste into Replit Agent “context” / initial message)

OPENCouncil is a monorepo (client + server + shared + scripts) that powers a municipal-document-grounded chat assistant. In production, the chat web app (Express API + React client) runs separately from crawler jobs. The crawler downloads municipal PDFs from town websites (handling JS-rendered pages and Cloudflare edge cases), stores documents in S3, and updates a DB queue of “documents to ingest.” An ingestion process uploads documents into a Gemini File Search store (or similar retrieval store), and the chat pipeline retrieves those documents to answer questions with citations. There is an OCR workflow to handle “image-only” PDFs; some worker logic appears to run from the server side. The repo includes both legacy and V2 ingestion routes and likely needs clearer boundaries and better observability for token usage, retrieval payload size, and OCR coverage.
