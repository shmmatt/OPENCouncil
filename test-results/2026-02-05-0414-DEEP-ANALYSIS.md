## 🚨 Critical Patterns & Trends

### Pattern 1: **"Past Documents ≠ Current Information"**
We have tons of 2021-2022 meeting minutes, but zero current schedules. Users ask "when is the next meeting?" and we tell them about meetings from 3 years ago. Useless.

**Fix:** Prioritize current, forward-looking documents over historical archives.

---

### Pattern 2: **"State Law Fallback = Generic Failure"**
When town-specific docs are missing, the pipeline falls back to NH state law. Technically correct, but not helpful.

Example:
- Q: "When are property taxes due in Ossipee?"
- A: "NH law allows towns to set their own due dates... [RSA 76:15a]"
- User wants: "July 1 and December 1"

**Fix:** Get town-specific implementation documents, not just state enabling legislation.

---

### Pattern 3: **"Process Documents > Reference Documents"**
Questions about "how do I..." do better than "when/where/what is..."

Why? Because we have state RSAs that describe processes (how to register to vote, how to request a variance), but we don't have current operational info (meeting schedules, office hours, fee amounts).

**Fix:** Balance procedural docs with operational/current data.

---

### Pattern 4: **"Contact Info is Table Stakes"**
Every Tier C answer ends with "contact the town office for more information." But we can't tell them:
- Office hours
- Phone number
- Staff names
- Email addresses

**Fix:** Scrape and maintain current contact directories as foundational data.

---

### Pattern 5: **"Bartlett, Madison, Albany = Database Errors"**
Multiple DB errors for towns without configured stores:
```
[StoreResolver] Failed to resolve store for Bartlett
[StoreResolver] Failed to resolve store for Madison
[StoreResolver] Failed to resolve store for Albany
```

They fall back to statewide store, which is why answers still work (barely).

**Fix:** Configure stores for all Carroll County towns or improve fallback logic.
